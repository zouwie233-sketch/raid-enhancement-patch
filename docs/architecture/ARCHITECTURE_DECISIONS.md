# 已确认架构决策

状态：已确认  
确认日期：2026-08-01  
适用基线：`0.9.1.12-raid-registration-lifecycle-hotfix`

## ADR-001：支援令牌冷却跨正常重启保留

### 决策

支援令牌冷却属于世界玩法状态，必须跨正常停服和重新进入存档保留。

### 设计约束

- 冷却归属于当前服务器世界，而不是 Java 进程或全局 `config` 目录。
- 以玩家 UUID 和令牌类型组成稳定键。
- 使用世界时间的到期 tick；同一世界重启后继续计算剩余时间。
- 已到期记录在加载或有预算的维护阶段删除。
- 不得通过退出主菜单、重启服务器或切换维度绕过冷却。
- 当前内存格式首次迁移时没有可恢复的旧磁盘数据，因此迁移版本会从空冷却表开始，并在变更报告中明确说明。

### 不采用的方案

- 不在不同存档之间共享冷却。
- 不使用系统时间替代世界时间。
- 不在每 tick 同步写盘。

## ADR-002：村庄防御损伤和评级跨袭击中途重启恢复

### 决策

袭击尚未完成时，村庄防御损伤、惩罚和最终评级输入必须完整恢复。

### 必须持久化的事实

- 防御失败次数。
- 超时惩罚次数。
- 村民受损事件次数。
- 超时导致的村民受损事件次数。
- 已准备波次和当前逻辑波次。
- 已确认的结算参与者。
- 影响最终评级和奖励的其他累计量。

### 设计约束

- 只在事件或阶段变化时标记脏数据，不进行每 tick 磁盘写入。
- 实体缓存、消息冷却和临时扫描结果不进入永久数据。
- 世界实体本身由 Minecraft 存档；Mod 只保存重新关联所需的稳定 UUID 和领域事实。
- 重启不得清除惩罚，也不得重复计算同一损伤事件。

## ADR-003：datapack 支持 `/reload`，活动袭击使用规则快照

### 决策

波次编成、特殊敌人池、奖励和礼物等数据定义支持 `/reload`。已开始的袭击继续使用创建时的规则快照，新袭击使用重载后的规则。

### 设计约束

- 配置重载先完整解析和校验，再原子替换当前注册表。
- 活动袭击保存规则版本、内容指纹和恢复所需的已解析关键规则。
- 重启恢复不能只依赖当前 datapack；否则管理员在袭击中途更换数据包会改变未完成波次。
- 非法实体 ID、负数量、超限数量和缺失必填字段必须在重载阶段报告。
- 重载失败时继续使用上一份完整有效注册表。
- 客户端展示配置可以更新，但不得反向修改服务端活动袭击快照。

## 共同结论

以上三项决策都要求先建立服务器/世界作用域，再迁移持久化。不得直接把当前静态表写入全局 `config` 文件作为过渡方案。
